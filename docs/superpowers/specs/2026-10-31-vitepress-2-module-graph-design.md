# Module-graph для VitePress 2.0.0-alpha.21

Статус: согласовано пользователем 2026-10-31. Часть выбранной точечной миграции
`Cringe-Driven-Development-Team/docs` на VitePress `2.0.0-alpha.21`.

## Цель и границы

Адаптировать `@tp-prepare/vitepress-module-graph`, проверить реальную интеграцию
и выпустить пакет через существующий workflow. Пользователь явно включил
работу над пакетом и его выпуск в задачу миграции docs.

Сохранить граф, фильтры, карточки, архив, меню, шапки треков, подстраницы,
загрузчик и CLI. Формат Markdown/YAML и публичные экспорты менять только при
доказанной необходимости миграции. Совместимость с VitePress 1.x и иными
alpha-версиями специально не добавляем. Другие пакеты монорепозитория
обновлять только если этого требует действующий механизм выпуска.

## Проверенные факты

База: `main` на `00e8548745e6f04933f798a73f9c395c1eb4febd`.

- Пакет имеет версию `0.3.0`; peer dependency VitePress — `^1.6`, dev dependency
  — `1.6.4`. Vue peer — `^3.5`, dev — `3.5.43`.
- `src/node/loader.ts` возвращает объект `watch`/`load`; типы и модель данных
  независимы от рендера VitePress.
- `src/theme/index.ts` регистрирует компоненты через Vue App и предоставляет
  `trackHeader` для слота `doc-before`. Компоненты используют `useData` и
  `withBase` из VitePress; совместимость нужно проверить в браузере.
- `test:site` копирует пакет в тестовый сайт как установленную зависимость,
  проверяет типы, production build, HTML и dev-сервер.
- `.github/workflows/ci.yml` запускает сборку, типы, тесты, проверку архивов и
  тестовые сайты. Версии и CHANGELOG ведёт release-please; `release.yml`
  публикует выпущенные пакеты через npm OIDC.

## Подходы

Выбрана точечная миграция обоих репозиториев: проверить существующие точки
подключения и исправить только реальные несовместимости. Альтернатива со
своей новой интеграцией Mermaid относится к docs и отвергнута как
преждевременное расширение задачи. Переписывать граф для нового движка
оснований по результатам чтения кода нет.

## Решение

Предложение автора спеки: установить VitePress `2.0.0-alpha.21` точной версией
в `peerDependencies` и `devDependencies` пакета, обновить `bun.lock`, тестовый
сайт и требование в README. Зафиксировать изменение требования как breaking
change для release-please. Версию пакета и CHANGELOG вручную не назначать.

Проверить `createModulesLoader`, регистрацию глобальных компонентов, слот
`doc-before`, SSR, гидратацию, ссылки с base и CSS после обновления reset
VitePress. Существующий `vite.ssr.noExternal` в примере подключения сохранить,
если проверка не докажет необходимость изменения. Новых слоёв совместимости
или конфигурационных переключателей не добавлять.

Исправления кода, дополнительные регрессионные тесты и детали проверки архива
выбирает исполнитель по выявленным проблемам. Затрагивать только связанные
с миграцией зависимости и их транзитивный граф.

## Проверка и выпуск

1. Выполнить проверки из корневого README: `bun run build`,
   `bun run typecheck`, `bun run test`, `bun run test:packages`,
   `bun run --filter '*' test:site`.
2. Проверить архив именно module-graph вне workspace и браузерные сценарии
   графа, фильтров, карточки, архива, шапки трека и подстраницы в обеих темах,
   с корневым и вложенным base. Одной проверки SSR HTML недостаточно.
3. Передать локальный архив в рабочую область docs для интеграционной проверки
   до публикации. Работы в репозиториях не блокируют друг друга до этого шага.
4. После успешных проверок интегрировать изменение и release PR, проверить
   фактический выпуск через `release.yml`, наличие новой версии в npm,
   её VitePress peer dependency и установку в docs из реестра.

Временные ссылки на локальные архивы не входят в итоговые манифесты/lockfile.
Публикация вручную вместо действующего release workflow не входит в решение.
Конкретный номер выпуска определяется release-please после принятого изменения.

## Приёмка и ограничения

Пакет проходит проверки на `2.0.0-alpha.21`, интерактивные сценарии работают,
новая версия опубликована и устанавливается в docs без рассогласования его
peer dependency с целевым VitePress. Старые пользовательские данные модулей
читаются без миграции формата. Alpha-статус движка остаётся ограничением.

Общий контракт миграции хранится в `Cringe-Driven-Development-Team/docs`:
`docs/superpowers/specs/2026-10-31-vitepress-2-migration-design.md`.
